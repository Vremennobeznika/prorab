# Прораб 0.4.1: проекты и диалоги

На Windows Прораб открывается в отдельном окне приложения. Внешний браузер не запускается.
Окно использует системный Microsoft Edge WebView2 Runtime; если его нет, установщик
предложит его установку через подписанный загрузчик Microsoft (для этого нужен интернет).

1. Во вкладке **Модели** включите модель и сохраните её ключ, если он нужен.
2. В разделе **Проекты** выберите папку: **Выбрать папку…** в Windows или введите полный путь.
   Файлы остаются на месте; копирования в папку приложения нет.
3. Нажмите **Новый диалог**, выберите агента и модель. Автовыбор использует включённые
   модели по порядку; конкретная модель закрепляется за диалогом.
4. Отправьте задачу. Следующее сообщение продолжает этот диалог, включая предыдущие
   вопросы, ответы и результаты инструментов. После закрытия программы диалоги остаются слева.
5. Подтверждайте запись файлов и команды только после просмотра действия. Остановка
   отменяет ожидающие разрешения; уже выполненные действия автоматически не откатываются.

План появляется, когда агент вызывает `update_plan`. Это его рабочий список, а не доказательство
успешной проверки. `delegate_agent` передаёт отдельное поручение специалисту для чтения и ревью:
его запуск и результат видны в журнале. Специалист не может менять файлы, запускать команды
или создавать других агентов. Ограничение — два поручения на одно сообщение.

В длинном диалоге в модель передаются последние восемь завершённых шагов в пределах бюджета
контекста. Большие и прерванные шаги сокращаются целиком, чтобы не оставить вызов инструмента
без результата. Журнал сообщает, сколько шагов сокращено или осталось за пределами контекста.
Детальная сохранённая история не удаляется. Важные постоянные решения можно сохранить
во вкладке **Память**; она включается отдельно от истории текущего диалога.

Истории разных диалогов не смешиваются. Папка закреплена за проектом; инструменты ограничены
этой папкой. Локальный режим агента ограничивает и его делегированные проверки. Поиск прошлых
заданий для памяти ограничен текущей папкой проекта.

Данные хранятся в `%LOCALAPPDATA%/Prorab` (`PRORAB_USER_DIR` для разработчика):
`data/sessions/` — проекты, планы и диалоги; `data/runs/` — журнал запусков;
`data/memory.json` — явно сохранённые заметки. Удаление приложения оставляет эти данные.

Это собственный движок Прораба. Готовые пользовательские агенты загружаются из
`agents/<id>/agent.json` и `SKILL.md`; инструменты и провайдеры подключаются через существующие
реестры JavaScript. Произвольные плагины DeepSeek Harness и MCP пока не поддерживаются.

Проверки из каталога исходников:

```sh
node --test
node qa/smoke-installed.mjs
node qa/load-agent.mjs
python3 qa/workspace-browser.py
python3 qa/memory-browser.py
```

Браузерные проверки требуют Python Playwright и Chromium. Нативное окно дополнительно
проверяет Windows CI: после старта `.exe` он ждёт успешного отображения страницы WebView2
и наличия собственного окна. Ответы настоящих внешних моделей проверяются отдельно с вашим ключом.

## Ключ модели

Во вкладке «Модели» вставьте ключ через Ctrl+V, контекстное меню или кнопку «Вставить», затем нажмите «Сохранить». Отметка «Ключ сохранён» подтверждает запись в профиль. Пустое поле после сохранения нормально: сохранённый ключ не возвращается в интерфейс. Для замены введите новый.

Ключи записываются в `credentials.json` в папке профиля пользователя, отдельно от общих настроек. Прежние ключи из `.env` также читаются. После перезапуска сохранённый ключ продолжает использоваться. Сохранение не проверяет действительность ключа у внешнего сервиса.
