# Память, поиск и критерии готовности

## Для пользователя

На вкладке **Память** можно сохранить предпочтение или решение, изменить его и удалить.
Общие предпочтения учитываются независимо от слов задания; остальные заметки подбираются
по совпадению слов. Чтобы применить их, на пульте включите **Использовать память и прошлые задания**.
Эта настройка изначально выключена и запоминается в текущем браузере.

Заметка по умолчанию доступна только агентам с режимом **Только локальные модели**.
Для обычного агента снимите эту отметку, если согласны передавать текст выбранной модели,
включая облачную. Параметр относится к режиму агента, а не к наличию Ollama на компьютере.

Поиск на вкладке Память показывает заметки и успешные прошлые задания, в том числе старше
последних 50 карточек пульта. Кнопка **Сохранить решение** переносит результат в редактор:
проверьте его и сохраните явно. Программа не выдаёт ответ модели за проверенный факт.

Для автоматического подбора истории используются только успешные задания того же агента,
запущенные с включённой памятью. Старые задания без этой отметки автоматически не передаются.
Кнопка **Не использовать в памяти** исключает задание из последующего подбора, сохраняя журнал.
Заметки из него удаляются отдельно. Удаление не убирает контекст из уже запущенных заданий.

Перед запросом подбираются до пяти заметок и трёх прошлых заданий, в пределах небольшого
бюджета текста. Общие предпочтения имеют приоритет; в журнале видны идентификаторы выбранных
источников. Много длинных общих заметок может вытеснить остальные — храните их краткими.

В форме задания раскройте **Как понять, что задача готова** и укажите критерии.
Помощник получает их вместе с заданием и инструкцию перечислить проверенное и непроверенное
по каждому пункту. Это не независимая проверка результата: отчёт модели может ошибаться.

Агенты, умеющие читать файлы, получили инструмент `search_files`: точный поиск текста
без учёта регистра с путём, номером строки и фрагментом. Он читает актуальные файлы,
не строит внешний индекс и не вызывает дополнительную модель. Это не семантический поиск
и не анализ дерева кода. Скрытые файлы, ключи с известными именами/расширениями, ссылки,
типовые зависимости и каталоги данных пропускаются. Произвольные секреты в обычных файлах
автоматически распознать нельзя. Найденный текст, как и read_file, может уйти выбранной модели.
Поиск ограничен 200 файлами, 4 МБ прочитанных данных, 3000 просмотренными записями,
глубиной 12 и 10 совпадениями; достижение лимита явно сообщается.

## Хранение и проверки

Заметки находятся в `data/memory.json`, история — в `data/runs/`.
В установленном режиме это подкаталоги `%LOCALAPPDATA%/Prorab`, либо `PRORAB_USER_DIR`.
Локальные источники не передаются агентам с доступом к облачным моделям.
Сохранение заметок атомарное; повреждённый файл не перезаписывается. При недоступности
памяти задание продолжается без неё с явным событием в журнале.

Дополнительные зависимости и миграции не нужны. Из каталога распакованных исходников:

```sh
node --test
node qa/smoke-installed.mjs
node qa/load-agent.mjs
# Необязательная проверка интерфейса: Python Playwright и установленный Chromium
python3 qa/memory-browser.py
```

89 тестов проверяют в том числе реальный HTTP-запрос к тестовому серверу модели,
повторное открытие памяти, отзыв согласия на использование истории, ограничения локальных
данных, повреждённое хранилище, передачу критериев и поиск по свежим файлам.
Браузерный сценарий проверяет создание/изменение/удаление, поиск, сохранение решения,
использование памяти, подтверждение записи и отсутствие переполнения на четырёх ширинах.
Внешние ИИ-сервисы и Windows-установщик этими проверками не проверяются.

## Откуда взяты идеи

Реализация написана для Прораба на JavaScript, без переноса чужого кода или зависимостей.

- [HyperMnesia](https://github.com/Recluse/HyperMnesia): долговременная память, источники,
  ограниченная подстановка контекста, явная диагностика недоступности.
- [srose69/retriforever](https://github.com/srose69/retriforever): локальный поиск с точными
  путями и строками, без пересказа дополнительной моделью. Tree-sitter, BM25 и MCP не переносились.
- [srose69/hecatoncheire](https://github.com/srose69/hecatoncheire) и
  [srose69/ai-sdlc](https://github.com/srose69/ai-sdlc) (форк AlexMKX/ai-sdlc): явные
  критерии результата и различение выполненной работы и её проверки.
  Автоматический цикл независимых Writer/Validator/Observer здесь не реализован.

У остальных просмотренных репозиториев профиля преимущественно другой предмет:
обучение моделей, CUDA-операции и инфраструктура. Они не добавлены в зависимости Прораба.
